Documentos y reportes con Quarto

Cada lunes, Gabriela copiaba gráficos de R a un documento, actualizaba a mano las cifras del texto y lo mandaba. Un lunes se olvidó de cambiar un número. Con Quarto, el texto, el código y los resultados viven en un mismo archivo que se regenera con un comando, y un parámetro produce un reporte por barrio sin copiar nada.

Programación literaria: texto, código y resultado en un mismo archivo

El lunes a las 9, Ernesto Salas leyó en el informe semanal que Las Lomas perdía «unas 30 bicis cada mañana». Cecilia Mora, que maneja el camión, sabía que eran más. Tenía razón: la cifra era de un informe viejo. Gabriela armaba el documento a mano cada semana: corría el guion en R, exportaba los gráficos como PNG, los pegaba en el procesador de texto y actualizaba los números del texto uno por uno. Esa semana cambió el gráfico, pero se olvidó de una frase.

El problema no es el descuido de Gabriela: es el método. Mientras el análisis y el documento sean dos cosas separadas unidas por copiar y pegar, tarde o temprano se desincronizan. La solución es que sean una sola cosa: un archivo que tiene el texto, el código que calcula y el lugar donde va cada resultado, y que se convierte en el documento final ejecutando el código cada vez.

Imagínalo así

Piensa en una receta escrita en una libreta frente a una receta que se cocina sola. En la libreta dice «hornear 40 minutos» y al lado pegas una foto del pastel de la última vez; si cambias los ingredientes, la foto queda vieja. Un documento con código es como una receta que, cada vez que la abres, cocina el pastel de nuevo con los ingredientes de hoy y pone la foto recién sacada. No hay foto vieja posible.

La idea tiene nombre y autor. En 1984, Donald Knuth, el informático de Stanford que creó el sistema tipográfico TeX, propuso la programación literaria (literate programming): escribir los programas como textos para personas, con el código intercalado en la explicación, y que una herramienta separe el código para ejecutarlo y el texto para leerlo. En el análisis de datos la idea se volvió práctica con Sweave (2002), que mezclaba R con LaTeX, y sobre todo con knitr (2012), de Yihui Xie, que ejecuta los bloques de código de un documento y pega los resultados en su lugar. Al conjunto se le llama también investigación reproducible (reproducible research): cualquiera con el archivo y los datos obtiene el mismo documento.

Para Gabriela, la consecuencia es concreta: la frase del informe ya no dice «unas 30 bicis», sino que tiene escrito un pedacito de código, r neto, entre comillas invertidas, y el número se calcula cada vez que se genera el documento. Si los datos cambian, la frase cambia sola.

De R Markdown a Quarto

En 2014, RStudio (hoy Posit) publicó R Markdown: documentos en Markdown (un formato de texto plano con marcas simples, como **negrita** o ## Título) con bloques de código de R. El paquete rmarkdown llamaba a knitr para ejecutar el código y luego a Pandoc, el conversor universal de documentos escrito por John MacFarlane, para producir HTML, PDF o Word. Durante una década fue la manera normal de escribir reportes en R, y alrededor crecieron paquetes para libros (bookdown), sitios web (blogdown, distill), presentaciones (xaringan) y tableros (flexdashboard).

En 2022, Posit publicó Quarto, la siguiente generación. La diferencia de fondo es que Quarto no es un paquete de R: es un programa aparte, que se instala como cualquier aplicación y se usa desde la terminal, y que funciona igual con R, Python, Julia u Observable JS. Para el código de R usa el mismo knitr de siempre; para el de Python, Jupyter. Y lo que antes estaba repartido en muchos paquetes (documentos, libros, sitios, presentaciones, tableros) ahora es un solo sistema con una sola sintaxis.

Un archivo Quarto termina en .qmd y tiene tres partes, cada una en su propio lenguaje. Arriba, entre dos líneas ---, el encabezado YAML (YAML header; YAML es un formato de configuración legible, con pares clave: valor) dice el título, el formato de salida y los parámetros. Después viene el texto en Markdown. Y entre el texto, los bloques de código (code chunks), que se abren con tres comillas invertidas y el lenguaje entre llaves. Además, dentro del texto se puede escribir código en línea entre comillas invertidas, que se reemplaza por su resultado:

---
title: "Viajes por barrio"
params:
  barrio: "Las Lomas"
format: html
---

El barrio tiene `r nrow(b)` estaciones y pierde **`r abs(neto)` bicis** cada mañana.

En la página, los bloques de los ejemplos de Quarto van con cuatro comillas invertidas en vez de tres, para que no se confundan con los bloques del propio curso. Quarto y knitr aceptan tres o más; en tus archivos puedes usar tres.

Si ya tienes documentos de R Markdown (.Rmd), Quarto los renderiza casi sin cambios: entiende su encabezado y sus bloques. Para proyectos nuevos, la recomendación de Posit desde 2022 es Quarto. RStudio y Positron lo traen integrado (un botón «Render» y una vista previa que se actualiza al guardar), y el paquete de R quarto permite llamarlo desde la consola.

Bloques de código, opciones y salidas

Cada bloque de código se puede configurar con opciones que se escriben al principio del bloque, en líneas que empiezan con #|. Las más usadas deciden qué parte del bloque llega al documento:

  • echo: si se muestra el código. En un reporte para quien no programa, echo: false; en material de clase, echo: true.
  • eval: si se ejecuta. eval: false muestra el código sin correrlo, útil para un ejemplo que el lector no puede ejecutar.
  • include: si el bloque deja algún rastro. include: false ejecuta el código y lo esconde entero, con su resultado. Es lo que se usa para cargar paquetes y preparar los datos al principio.
  • output: si se muestra el resultado (texto impreso, tablas y gráficos).
  • warning y message: si se muestran los avisos y los mensajes de R.
  • fig-cap, fig-width, fig-height y fig-alt: el pie, el tamaño y el texto alternativo de los gráficos.
  • code-fold: true: en HTML, deja el código plegado detrás de un botón «Code».

Las opciones que valen para todo el documento van en el encabezado, bajo execute: (por ejemplo, execute: echo: false para esconder el código de todos los bloques), y un bloque puede cambiarlas para sí mismo. R Markdown escribía las opciones dentro de las llaves ({r, echo=FALSE}); Quarto también lo acepta, pero la forma con #| es la recomendada porque es igual para todos los lenguajes.

Reportes con parámetros: uno por región con el mismo archivo
Adriana Celis, de la oficina de planificación de la alcaldía, le pidió a Gabriela «el mismo informe, pero uno por barrio», para mandarle a cada junta vecinal el suyo. La tentación es copiar el archivo seis veces y cambiar el filtro en cada copia. Seis copias son seis lugares donde equivocarse la próxima vez que cambie algo.
Quarto tiene una respuesta mejor: los parámetros (parameters). En el encabezado se declaran con un valor por omisión:
params:
  barrio: "Las Lomas"
Dentro del documento, params$barrio vale lo que se pida al renderizar. El primer bloque filtra con est[est$barrio == params$barrio, ], el título de la sección es el código en línea r params$barrio y todo lo demás se calcula sobre ese filtro. Para cambiar el valor sin tocar el archivo, se pasa en la terminal con -P:
quarto render reporte.qmd -P barrio:"Ribera" --output reporte-ribera.html
Con el texto condicional se puede ir un paso más allá: una frase que cambia según los datos. Este código en línea escribe la recomendación que corresponde a cada barrio:
`r if (neto < -20) "Hace falta rebalanceo temprano." else "El balance es moderado."`
Hay que usarlo con cuidado: el texto condicional se lee como una conclusión, y alguien tiene que haber decidido el umbral de 20 bicis con criterio.

Presentaciones y tableros Quarto
El mismo .qmd puede producir otras cosas cambiando el formato. Con format: revealjs, cada título de nivel 2 (##) se vuelve una lámina de una presentación web hecha con reveal.js: se proyecta desde el navegador, tiene modo orador con notas, se puede exportar a PDF, y los gráficos y widgets van adentro, vivos. Con format: pptx sale un PowerPoint editable, útil cuando la oficina exige ese formato, aunque con menos control del diseño.
Desde la versión 1.4 (2024), Quarto hace también tableros (dashboards) con format: dashboard: una página organizada en filas, columnas y tarjetas, donde cada bloque de código es un panel. Una tarjeta puede ser un número grande (con value_box), un gráfico de ggplot2, un mapa de leaflet o una tabla de DT. Un tablero así es estático: se genera una vez con los datos del momento y es una página que se publica en cualquier lado. Si los widgets usan crosstalk, el lector puede filtrar y seleccionar dentro de la página, sin servidor. Si hace falta recalcular con lo que elige el lector, el tablero puede incluir componentes de Shiny (server: shiny), pero entonces necesita un proceso de R detrás, como en los capítulos 10 a 14.
Un caso real
Libros y artículos que se pueden regenerar. Buena parte de los libros abiertos de ciencia de datos en R, como «R for Data Science», «Advanced R» o el libro de ggplot2, se escriben con Quarto o con su antecesor bookdown: cada capítulo es un archivo con texto y código, y el libro entero se regenera con un comando cada vez que cambia una versión de un paquete. Si un ejemplo deja de funcionar, la construcción falla y los autores se enteran antes que los lectores. Varias revistas científicas aceptan hoy artículos escritos así, y algunos equipos de estadística pública publican sus informes periódicos con el mismo método: el informe de cada mes es el del mes anterior con datos nuevos, no un documento rehecho a mano.


Publicar en HTML, PDF y Word
Un mismo documento puede declarar varios formatos en el encabezado y generar todos a la vez:
format:
  html:
    embed-resources: true
    toc: true
  docx: default
  typst: default
Cada formato tiene sus condiciones. HTML es el más completo: admite widgets interactivos, código plegable y tablas que se ordenan; con embed-resources: true sale un solo archivo autónomo que se manda por correo. Word (docx) sirve cuando alguien va a seguir editando el texto; los gráficos entran como imágenes y los widgets no funcionan. Se le puede dar una plantilla con los estilos de la organización (reference-doc). PDF necesita un motor de composición: Quarto puede usar LaTeX, con una distribución mínima que se instala con quarto install tinytex, o Typst, un sistema más nuevo y rápido que viene incluido con Quarto (format: typst). Los widgets tampoco funcionan en PDF.
Para publicar en la web hay varias salidas. quarto publish sube el resultado a servicios como Quarto Pub (gratuito y público), GitHub Pages, Netlify o Posit Connect. Un proyecto Quarto (una carpeta con un archivo _quarto.yml) convierte muchos .qmd en un sitio web o un libro con índice, búsqueda y navegación. Y como un HTML de Quarto es una página estática, también se puede copiar a cualquier servidor web, sin R ni Quarto instalados.
Una advertencia práctica antes de automatizar: el reporte es tan reproducible como su entorno. Si el bucle de los lunes corre en otro equipo con otra versión de ggplot2, el gráfico puede cambiar; para eso está renv, del capítulo 06, que congela las versiones de los paquetes junto al proyecto.

La idea clave
Un reporte hecho con copiar y pegar se desincroniza; uno escrito con Quarto se regenera. El archivo .qmd tiene un encabezado YAML con el formato y los parámetros, texto en Markdown con código en línea y bloques de código con opciones que deciden qué llega al documento. quarto render ejecuta el código con knitr (o Jupyter) y le pasa el resultado a Pandoc, que produce HTML, PDF, Word, presentaciones o tableros desde el mismo archivo. Los parámetros convierten un reporte en muchos: el mismo .qmd con otro barrio es otro informe, sin copias. El reporte deja de ser un documento que se edita y pasa a ser un programa que se ejecuta.


Pruébate
Pruébate
¿Qué diferencia hay entre include: false y echo: false en un bloque?
echo: false esconde el código pero muestra el resultado; include: false ejecuta el código y no deja ningún rastro en el documento, ni código ni resultado. Las variables que crea sí quedan para los bloques siguientes.
¿Qué hace knitr y qué hace Pandoc cuando ejecutas quarto render sobre un documento con R?
knitr ejecuta los bloques de R y deja un Markdown con los resultados pegados; Pandoc convierte ese Markdown en el formato final (HTML, PDF, Word, láminas).
¿Cómo generas el reporte de Ribera sin modificar reporte.qmd, que tiene barrio: "Las Lomas" por omisión?
Pasando el parámetro al renderizar: quarto render reporte.qmd -P barrio:"Ribera", o desde R con quarto_render("reporte.qmd", execute_params = list(barrio = "Ribera")).
Un reporte tiene un mapa de leaflet. ¿En qué formato conviene publicarlo y por qué?
En HTML: es el único donde el widget funciona, porque necesita un navegador con JavaScript. En PDF o Word no hay navegador.
¿Qué ventaja tiene embed-resources: true en un HTML de Quarto?
Mete las imágenes, los estilos y el JavaScript dentro del mismo archivo, así el HTML se puede mandar por correo o copiar sin carpetas adicionales.
¿Por qué Quarto puede renderizar documentos con Python además de R?
Porque es un programa aparte, no un paquete de R: para los bloques de R usa knitr y para los de Python, Jupyter, y en los dos casos el resultado pasa por Pandoc.
